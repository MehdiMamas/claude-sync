Members: invite, remove, transfer, leave, discover: edge cases

Created 2026-11-26. Updated 2026-11-26.

As a host, I want to see what happens when it goes wrong while I manage who is in my group, so that only the people I trust get my setup even then. Click a step to open its screen. The flow behind it.

Acceptance criteria: The user sees what went wrong in words, and what to do next. Nothing is lost or half-written.
  1. Transfer requested
    System: GitHub emails the new owner; nothing moves until they accept. Calls POST /repos/{owner}/{repo}/transfer.
  2. Not accepted in time, or declined
    System: The old host stays host and can ask again.
  3. Invite by GitHub name
    System: A collaborator invitation with push rights. Calls PUT /repos/{owner}/{repo}/collaborators/{login}.
  4. Unknown name: nothing sent
    System: GitHub answers 404 for the login.
  5. List collaborators
    System: Permissions decide who is host (admin). Calls GET /repos/{owner}/{repo}/collaborators.
  6. Member: host-only actions hidden
    System: The buttons are not shown; a 403 from GitHub would say only the host can do that.
