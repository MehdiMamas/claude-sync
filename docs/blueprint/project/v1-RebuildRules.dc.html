Rebuild spec 2: behaviour rules

Exact rules a builder follows without reading the old code: timings, merge and conflict rules, what is dropped, retries, rate limit, caches, OS differences and the messages people see. Created 2026-11-26. Updated 2026-11-26.

#RuleBehaviourEvidence
1Sync intervalCheck every 60 s (choices app.intervalSecs, minimum 15 s). Pending invitations every 15 min. Update check at start and every 6 h. Rename check and host member pass at most every 10 min per group. File edits are debounced 2 s. A person can pause. Interval: default 60 s, minimum 15 s, the settings field clamps 15 to 3600. A downloaded update installs at a quiet moment: no sync running, window hidden, and the window last shown at least 10 minutes ago (or never); also on Quit or Restart to update.app/src-tauri/src/config.rs:47-50; watch.rs:126; docs/architecture.md:157; commands.rs:785; updates.rs:16,41-50,200-235
2Head check and cacheOne GraphQL call per tick reads name and default-branch head of every group repo and the personal repo. Unchanged head costs no REST call. Every REST GET uses If-None-Match; a 304 returns the cached body (256 entries). Non-GET and answers without an ETag are never cached. The head ETag is also saved in head.json.crates/core/src/github/graphql.rs; github.rs; docs/architecture.md:154-156
3Retries and backoffGET requests and network failures retry up to 3 attempts, waiting 0.5 s then 1 s (doubling). 502 to 504 retry for GETs only. Non-GET calls are not retried on 5xx.crates/core/src/github.rs:381,520-540,581-583
4Rate limit403 or 429 with Retry-After, or x-ratelimit-remaining 0, or a 403 naming the secondary limit (60 s) sets one shared limited-until time per resource (core and GraphQL apart). While it is ahead no request goes out. The loop sleeps to the reset plus 5 s (at most 1 h), then runs a full sync. Message: core error, tray and notification "GitHub limit reached, resumes at <local time>" (weekday added when not today); the window shows "GitHub limit reached, resumes <time>" (no "at", no weekday).crates/core/src/github.rs:306-312,564-628; docs/architecture.md:158
5Fetch only changesWhen the head moves, files whose git blob sha matches the base are reused with no request; only other paths are fetched. Open proposals are re-read only when a PR head sha or updated_at changed.AGENTS.md (Gotchas); remote.rs
6Three-way merge, groupsPer file with base B, local L, remote R: L equals B takes R; R equals B keeps L and pushes it; L equals R nothing. All three differ: JSON object files (settings.shared.json, claude-sync.json) merge key by key, a key both changed differently takes remote; other files are a conflict: remote wins and the local copy is saved under conflicts/<group>/<UTC time>/<path>. Deletes follow the same table.docs/architecture.md:164-168; merge.rs:289-340
7PushBlobs, tree on the remote head tree, commit with the head as parent, PATCH the ref without force. 422 means someone pushed: fetch, merge, retry, at most 3 times. The secret scan runs on every added or changed file first; a hit blocks the commit and names file, line and pattern. Marker "claude-sync: allow-secret" on a line skips it.docs/architecture.md:170; secrets.rs:6
8Settings mergesettings.shared.json into ~/.claude/settings.json: objects merge by key, arrays get missing shared items appended, plain values take the shared value. A removed key leaves only if the local value still equals what the app set. Two groups setting the same value: the higher group wins and the clash shows on both group pages. Not objects: nothing merged and the app says so.docs/architecture.md:247-253; settings.rs
9Dropped as machine-specificFrom the personal settings view and group sharing: apiKeyHelper, permissions.additionalDirectories, canary overrides, any value or hook command holding an absolute path, values flagged as secrets. Choices drop absolute paths, apiKeyHelper and secrets automatically. Exactly: apiKeyHelper, permissions.additionalDirectories, canary (mod) overrides, any string that is or contains an absolute path, and any object holding a "command" (dropped whole). apiKeyHelper is also never applied from a group.crates/core/src/settings.rs:516-528; personal/settings_file.rs:54-71; AGENTS.md (Scopes); settings.rs:152-175,512-521,607-608
10Secret patternsgithub_pat_ (50+), sk-ant- (20+), ghp_ (36+), gh[orsu]_ (36+), AKIA + 16, xox[abpr]-, private key header, "access_token" and "refresh_token" fields. Same patterns redact logs and feedback.crates/core/src/secrets.rs:17-28
11Personal memory mergeSame three-way merge with its own base. MEMORY.md merges as a set of lines: a line one side removed is dropped, every other line of either side is kept, new remote lines go after the line that precedes them. Never a conflict. Two devices holding the same lines with CRLF versus LF are never pushed or rewritten; pushed index bytes are LF. Detail: remote new lines are inserted after their predecessor, exact duplicates are dropped, blank lines are kept; the line ending is CRLF if the local file has CRLF; a trailing newline is kept if either side has one.docs/architecture.md:406; AGENTS.md (Gotchas); personal.rs; personal/lines.rs:7-74
12Personal pass timingAfter each group sync: conditional head GET (304 free); a pass only when the remote moved, local files changed, the device was renamed, or a day passed. Sync now always runs one.docs/architecture.md:408
13Group order and clashesgroups[] is the priority list; new groups join at the end; reorder refuses a list that is not exactly the joined groups. The higher group wins a file, settings value or marketplace.docs/architecture.md:268-274,296
14Host-only actionsOnly the host (repo admin) updates a group; members propose through a PR named proposal/<...>. A branch rule named "claude-sync: only the host updates the group" enforces it. Revert makes a new commit, refuses merge commits and commits of 300 or more files.remote.rs:106-109,1010; docs/architecture.md:170
15Windows, macOS, LinuxmacOS and Linux: release app links ~/.local/bin/claude-sync to its binary at start, only if the folder exists and the name is free. Windows: no shim; the release exe is a GUI program so PowerShell shows no output unless piped. Login item: first run enables start at login once (autostart plugin); background start passes --background. Linux build is beta: tray and login item untested, Secret Service required.app/src-tauri/src/cli.rs:318-331; main.rs:1,60-72; config.rs:54; AGENTS.md (Command line); architecture.md:364
16Messages shownToast ok: "Code copied", "Up to date", "Joined <owner>/<repo>", "Created <owner>/<repo>", "Invited <login>. They get an invitation from GitHub.", "claude-sync is up to date". Toast error: "GitHub could not be reached. Try again in a minute.", "<n> group(s) had an error". Limit: core and tray "GitHub limit reached, resumes at <time>"; window "GitHub limit reached, resumes <time>". Group plugin warning: "Plugins in this group run code on every member’s machine; only join groups whose members you trust." Texts captured from the live window are on the screen frames; error texts for join, accept and sync are from code, not captured.app/ui/src/screens; group.rs:24; docs/architecture.md:158
17Sync gatesNot signed in: the pass fails with an error. Paused (and not a forced full sync such as Sync now): the pass ends with "Syncing is paused". Rate limited: core and tray "GitHub limit reached, resumes at <local time>" (the window shows it without "at"). Pause is saved in both state.json and the personal choices (app.paused).app/src-tauri/src/background.rs:84-242; tray.rs:62-75
18Lost access to a groupA 403 or 404 on a group repo (deleted, or the person was removed) counts as lost access (is_lost_access). The group is removed from this machine, the group order of the others is kept, a backup is kept, that group's entry in choices is reset, and a notification says group access ended.crates/core/src/engine.rs:1469-1482,1900-1915,2333-2341; background.rs lost_access
