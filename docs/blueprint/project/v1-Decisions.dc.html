Decisions

Created 2026-11-26. Updated 2026-11-26.

Decisions already built into v1. The chosen option comes from docs/architecture.md; the rejected options are the obvious alternatives and the reasons come from the same document, not from a record written at the time. Section numbers are in docs/architecture.md.

Sync through the GitHub API, not git

Section 6. Friends run the app on plain Windows and macOS PCs.

  • Chosen: REST and GraphQL calls with ETag and blob-sha reuse. No git binary, no clone.
  • Rejected: Shell out to git. Needs git installed and configured on every PC.
  • Rejected: Embed libgit2. A large native dependency for a few file reads.

Sign in with the GitHub device flow

Section 3. A desktop app has no web server to receive a redirect.

  • Chosen: Device code with a public client id and no secret; tokens in the OS keychain.
  • Rejected: Local redirect server. Needs a free port and a firewall prompt.
  • Rejected: Paste a personal access token. Long-lived, wide-scope secret in a text box.

Only the host changes a group; members propose

Section 5a and 5c. A group is a few friends sharing one setup.

  • Chosen: Host-only writes (Error::HostOnly) and proposal branches proposal/<login>-<UTC>.
  • Rejected: Everyone pushes. One bad edit reaches every member.
  • Rejected: Merge without review. Members could not stop a change to their own CLAUDE.md.

On conflict the remote wins and the local copy is kept

Section 6. Two sides changed one file.

  • Chosen: Remote wins, the local copy goes to conflicts/<group>/<UTC>.
  • Rejected: Auto-merge text. Merged settings can be invalid JSON.
  • Rejected: Ask on every conflict. Blocks a background sync on a prompt.

Personal memory in a private repo of its own

Section 16. Personal notes must not travel through a group.

  • Chosen: <login>/claude-sync-personal, off until the user turns it on.
  • Rejected: Store it in a group repo. Other members could read it.
  • Rejected: Sync through a cloud drive. Needs another account and tool.

A small relay for what needs a secret

Section 12. Releases and feedback issues need a maintainer token.

  • Chosen: A free Vercel project with TypeScript functions.
  • Rejected: Put the token in the app. Anyone could read it from the binary.
  • Rejected: Run a server. A cost and an always-on machine.
