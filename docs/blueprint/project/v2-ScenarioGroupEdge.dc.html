Create a group and invite a member: edge cases

Created 2026-11-26. Updated 2026-11-26.

As a host, I want to see what happens when it goes wrong while I create a group and invite a friend, so that my friends get my shared Claude setup even then. Click a step to open its screen. The flow behind it.

Acceptance criteria: The user sees what went wrong in words, and what to do next. Nothing is lost or half-written.
  1. Lock main to admins
    System: A ruleset so only the host pushes; members propose by pull request. Calls POST /repos/{owner}/{repo}/rulesets.
  2. Lock refused: host-only stays an app rule
    System: The ruleset is named "claude-sync: only the host updates the group"; on a plan without rulesets the state is unavailable and the app still sends changes only from the host.
  3. New group, type a name
    System: The form checks the name locally against GitHub repo name rules.
  4. Name taken: pick another
    System: GitHub answers 422 name already exists; the form keeps the text.
  5. Accept
    System: Accept, then read the repo (name, private, permissions). Calls PATCH /user/repository_invitations/{id}.
  6. No access: join refused
    System: 404 or 403 on accept or read; nothing is written locally.
  7. Also: Group: invite failed
    System: state "error: no such user".
