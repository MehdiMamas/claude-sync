Migration and upgrade from every older version

What the code does to an install made by an older version, step by step. Nothing is ever deleted. Created 2026-11-26. Updated 2026-11-26.

#Step or thingExact behaviour, values and errorsEvidence
1Trigger (v0 clone)Runs when ~/.claude-sync/.git exists, that is a v0 install (a git clone of a personal config repo). Until it ran, the state folder is ~/.claude-sync/app.crates/core/src/migrate.rs; paths.rs
2Backup folder~/.claude-sync-v0-backup-<UTC stamp> (a "-N" suffix if the name exists). An unfinished folder holding a .migrating marker is reused; the marker lists the app/ names that v0 does not have.crates/core/src/migrate.rs
3Move order1 everything except app/ and .git moves to <backup>/claude-sync. 2 app/* moves up one level (a name present in both keeps the app's copy; v0's copy goes to the backup). 3 the empty app folder is removed. 4 .git moves last. A rename that fails falls back to copy then remove.crates/core/src/migrate.rs
4v0 hooksHooks in ~/.claude/settings.json whose command contains both "claude-sync" and "--hook" are v0's and are removed. settings.json is first copied to settings.json.before-migration. Empty hook groups and an empty hooks key are pruned.crates/core/src/migrate.rs
5Message"Moved your old claude-sync setup to {path}. Turn on Personal memory in Settings to sync your CLAUDE.md and memories."crates/core/src/migrate.rs
6choices.json first loadWhen choices.json does not exist it is built once from the older files with ts 0: state.json (disabled, groups, paused, pollSeconds), jobs.json (autoAccept, accepted, enabled) and claude-md-review.json (review). After that the old fields are not read again, so the newer ts always wins.crates/core/src/choices.rs
7Keychain token0.1.1 and earlier stored a bare access token; later versions store JSON with refresh data. Both are read (a token never starts with "{"). A bare token without refresh expires on the first confirmed 401, then the user signs in again.crates/core/src/github/session.rs
8claude-md-review.jsonFormat 2. A format 1 file (older app) is read and its per-device review bool is dropped (review = None), so the device follows the group setting; a file with format above 2 fails with "{file} was written by a newer claude-sync (format N)".crates/core/src/review.rs:138-157
9MEMORY.mdA personal MEMORY.md held with different line endings (CRLF vs LF) but the same lines is never pushed or rewritten (#159); pushed index bytes are LF.crates/core/src/personal.rs merge_personal; AGENTS.md
10Group schemaSCHEMA = 1. A claude-sync.json with a larger schema opens read-only (SchemaTooNew: "group file schema {0} is newer than this app; update the app"). Unknown keys are kept on rewrite so an older app does not drop newer fields.crates/core/src/group.rs; error.rs:30
11UpdatesThe background loop checks every 6 h (UPDATES_EVERY_SECONDS) with tauri-plugin-updater against {relay}/api/update (Authorization: Bearer <GitHub token>, 60 s timeout); a newer bundle comes through /api/download/<id>. Without a relay URL: "this build has no relay URL (CLAUDE_SYNC_RELAY_URL), so updates are off"; not signed in: "sign in to check for updates".app/src-tauri/src/updates.rs:120-138; background.rs:434
12CLI linkOn macOS and Linux a release app links ~/.local/bin/claude-sync to its binary at startup, only if that folder exists and the name is free. Windows has no link (run the full path of claude-sync.exe; the GUI exe prints nothing unless piped, #149).AGENTS.md
