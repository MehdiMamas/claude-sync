Background sync tick: edge cases

Created 2026-11-26. Updated 2026-11-26.

As a group member, I want to see what happens when it goes wrong while I have changes arrive on their own, so that my setup stays current without me clicking even then. Click a step to open its screen. The flow behind it.

Acceptance criteria: The user sees what went wrong in words, and what to do next. Nothing is lost or half-written.
  1. Conditional GET of main per repo
    System: If-None-Match with the stored ETag; 304 means nothing to do. Calls GET /repos/{owner}/{repo}/commits/{default_branch}.
  2. Rate limited: wait until reset
    System: 403/429 with x-ratelimit-reset or retry-after; no call until then.
  3. Moved: read the tree
    System: Paths with blob shas; compared with the base in the store. Calls GET /repos/{owner}/{repo}/git/trees/{sha}.
  4. Offline: skip this tick
    System: A connect error marks offline; the next tick tries again.
  5. Also: Groups: sync failed
    System: state "error: sync failed".
  6. Also: Groups: plugin problem
    System: state "warning: plugin failed".
