GitHub client: GraphQL snapshots, request counters, pagination

How the app talks to GitHub: caches, GraphQL fallback, counters and paging. Created 2026-11-26. Updated 2026-11-26.

#Step or thingExact behaviour, values and errorsEvidence
1GET ETag cacheIn memory, URL to ETag and body. A repeat GET sends If-None-Match; a 304 returns the cached body. Non-GET calls and answers without an ETag are never cached. The head ETag is also in head.json and is not part of Head equality.AGENTS.md; crates/core/src/github.rs
2GraphQL heads (#144)One POST /graphql per tick: `query { r0: repository(owner:"o", name:"r") { id databaseId nameWithOwner defaultBranchRef { name target { ... on Commit { oid committedDate tree { oid } } } } } r1: ... }` for every group repo and the personal repo.crates/core/src/github/graphql.rs
3RepoSnapshot{database_id, name_with_owner, head}. A null repo or an object without data is left out. A repo with no default branch gets Head::empty().crates/core/src/github/graphql.rs
4FallbackAn answer without data gives Err "GraphQL answered without data: {errors}"; the engine then falls back to the REST checks for each repo. GraphQL has its own rate-limit bucket, apart from REST (limited_until is per resource).crates/core/src/github/graphql.rs; engine.rs
5Paginationget_pages follows Link rel="next": /user/repository_invitations?per_page=100 and /user/repos?affiliation=owner,collaborator&per_page=100. The triage script uses per_page=100&page=N up to MAX_PAGES = 10.crates/core/src/github.rs; relay/triage
6Counter: callersTask-local CALLER set by with_caller(name, fut); default "other". Callers in code: "tick" and "personal" (background.rs:65-78), "invitations" (background.rs:361), and scoped(caller) in commands.rs:35.crates/core/src/github/requests.rs; app/src-tauri/src/background.rs; commands.rs:35
7Counter: entriesEntry {caller, endpoint "METHOD normalized-path", result "200"|"304"|"other", count}. Snapshot {since, last10min, total}: 10 one-minute buckets; entries sorted by count, descending.crates/core/src/github/requests.rs
8Counter: normalizerepos/o/r becomes repos/:repo; users|orgs/x becomes :user; contents/... becomes :path; ref|refs|heads|tags segments become :ref; "a...b" becomes :range; digits, or hex of 7+ chars containing a digit, become :id.crates/core/src/github/requests.rs
9Counter: filerequests.json is written atomically into the state dir (paths.requests_file) every minute by the app; `claude-sync status --json` has a `requests` field; `status` prints top_lines in the form "{count:>5} {endpoint} {result} ({caller})".crates/core/src/github/requests.rs; cli.rs
10Rate limitsA 403/429 with reset sets rate_limited_until and the core error "GitHub limit reached, resumes at {time}" (weekday added when not today). The window shows "GitHub limit reached, resumes {time}" (no "at", no weekday; app/ui/src/limit.ts).crates/core/src/error.rs:14; github.rs
11Errors the user sees"not signed in"; "Your GitHub sign-in expired. Sign in again."; "GitHub returned {status}: {message}"; "network error: {0}". See the Messages frames for the rest.crates/core/src/error.rs:7-16
