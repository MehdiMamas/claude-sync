merge.rs · order, types, jsonfiles, three ...
Three-way file merge (base, local, remote): remote-only change -> take remote; local-only change -> push (deleted local files push None); same change both sides -> nothing; both changed, or both added differently -> conflict, remote wins, local copy kept in conflicts; delete vs edit conflicts in both directions; delete with other side unchanged -> delete pushed/applied. Conflicts sorted by path.ordermerge.rs:three_way
For JSON object files (settings.shared.json, claude-sync.json, and personal settings) merge is per top-level/nested key three-way: both-changed key -> remote wins and one conflict recorded with the lost local; equal values (any formatting) push nothing; non-object JSON side falls back to a whole-file conflict; with no base the objects union (remote key order first).ordermerge.rs:json

v0 merge of settings.shared.json into settings.json: new keys added, nested objects merged, arrays unioned (local order first, shared dups dropped), scalar conflicts -> shared wins, object over local scalar wins, local-only keys and key order kept, UTF-8 not escaped, written with LF; a type clash (e.g. object vs string, array vs object) skips only that key with 'permissions: ...' or 'permissions.allow: ...' in skipped, never values.
