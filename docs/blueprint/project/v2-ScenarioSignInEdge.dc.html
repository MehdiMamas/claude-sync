Sign in with GitHub (device code): edge cases

Created 2026-11-26. Updated 2026-11-26.

As a new user, I want to see what happens when it goes wrong while I sign in with my GitHub account, so that I can use the app without a separate password even then. Click a step to open its screen. The flow behind it.

Acceptance criteria: The user sees what went wrong in words, and what to do next. Nothing is lost or half-written.
  1. Poll every interval, slow down when told
    System: github::device::poll honours interval and slow_down (adds 5 s). Calls POST https://github.com/login/oauth/access_token.
  2. Code expired: Get a new code
    System: expired_token from GitHub ends the poll; nothing is stored.
  3. You chose Cancel on GitHub
    System: access_denied ends the poll; nothing is stored.
  4. Store the token in the keychain, read the login
    System: store::secrets writes one keychain entry; GET /user gives the login. Calls GET /user.
  5. Later: 401 on any call, sign-in expired
    System: The engine stops every loop, deletes the token and emits SessionExpired. The tray says "Sign in again".
  6. Also: Sign in: offline
    System: state "error: no connection".
  7. Also: Sign in: not available
    System: state "error: build without client id".
