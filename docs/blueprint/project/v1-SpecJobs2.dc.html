cron.rs · validation, constant, parse order, error ...
Accepted cron grammar (exactly 5 whitespace-separated fields, extra spaces ok): minute and hour = a number or comma list, digits only, minute 0..=59, hour 0..=23 (no *, ranges, steps, "+1", names, empty items, trailing comma); day-of-month and month MUST be literally "*"; day-of-week = "*" or comma list of 0..=6 numbers and ranges a-b (a<=b), 7 and names rejected. All lists are sorted and de-duplicated; a day list covering all 7 days becomes "every day".validationcron.rs:1-48
MAX_TIMES = 48 (hour x minute combinations per run day; Task Scheduler allows 48 triggers per task). 49 or more is rejected, 48 accepted.constantcron.rs:5-6
Schedule::parse checks in this order: split on any whitespace into exactly 5 fields; minute (max 59); hour (max 23); day-of-month and month both literally "*"; day of week; then the number of times. So `* * * * *` reports the minute error first. Numbers are u8 digits only: "05" is accepted as 5, "256", "+1", "-1" and " 1" are not.parse ordercron.rs:20-48
