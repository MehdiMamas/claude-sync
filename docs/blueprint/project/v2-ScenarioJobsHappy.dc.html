Scheduled jobs from a group: happy path

Created 2026-11-26. Updated 2026-11-26.

As a group member, I want to accept a scheduled job before it runs, so that nothing runs on my computer without my yes. Click a step to open its screen. The flow behind it.

Acceptance criteria: No job is scheduled before its yes. Offline runs are skipped, not run.
  1. Group ships schedules.json
    System: engine::jobs::validate: at most 20 jobs, prompt 4096 bytes, id rules, timeout 1 to 240 minutes, allowed flags only.
  2. Review the job
    System: Prompt, schedule, folder, timeout, permission mode (bypassPermissions warned) and args (--chrome, --model, --effort only) shown in full.
  3. Accept and schedule
    System: The engine writes the OS task: Task Scheduler, launchd or a systemd user timer.
  4. OS runs claude-sync run-job
    System: The app binary (desktop) or the headless CLI (servers, WSL) takes the job lock, sets PATH from the login shell, runs claude with the timeout.
  5. Keep the 20 newest logs
    System: logs/jobs/<id>/<UTC stamp>.log; the result shows on the Jobs card.
  6. State: Waiting for yes
    System: UML state machine: Job.
  7. State: Scheduled
    System: UML state machine: Job.
  8. State: Running
    System: UML state machine: Job.
  9. State: Turned off
    System: UML state machine: Job.
