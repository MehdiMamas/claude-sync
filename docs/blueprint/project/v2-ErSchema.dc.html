Not in SQLite: the token (keychain), personal choices (choices.json in the personal repo, cached in a settings row), job logs (logs/jobs/<id>/<UTC>.log, 20 kept). Security: the file is mode 0600; no secrets are stored in it; secret-scan runs before any blob is pushed. Import: store::import_v1 reads every v1 state file once: state.json, manifest.json, jobs.json, notifications.json, requests.json, app.json, activity.json, ssh-peers.json (this machine id and alias), settings-owned.json, plugins.json, packs.json, outbox/ (into feedback_queue), conflicts/, per group head.json with its ETag, status.json and claude-md-review.json, personal/state.json, jobs/<id>/last-run.json. The base trees (groups/<g>/base/, personal/base/ and the per-kind off folders), packs-setup/, logs/jobs/ and backups stay as files in place and the store points at them, so the first v2 pass is never a first sync. It waits while daemon.lock is held. It never moves or renames ~/.claude-sync: ~/.claude/CLAUDE.md imports ~/.claude-sync/groups/<owner>__<repo>/CLAUDE.md, and the token, sync.lock and daemon.lock live there. store.db sits beside the v1 files, which stay untouched as the way back.
