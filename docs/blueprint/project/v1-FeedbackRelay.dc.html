Feedback 2: the relay side

Auth, limits, statuses, the three endpoints and the feedback flow with the attachments repo. Created 2026-11-26. Updated 2026-11-26.

#Step or thingExact behaviour, values and errorsEvidence
1AuthBearer GitHub token; the relay calls GET /user. Login cached 10 min (key SHA-256 of the token, at most 1000 entries). BLOCKED_GITHUB_USERS logins get 403.relay/lib/auth.ts; relay/README.md
2Rate limitsAPI_LIMIT 120 calls per hour per login; FEEDBACK_LIMIT 5 feedback per hour per login; sliding windows in memory; at most 10,000 keys.relay/lib/ratelimit.ts
3Statuses400 bad parameters or body; 401 missing or rejected token (WWW-Authenticate: Bearer); 403 blocked login; 404 unknown asset; 413 screenshot over 3 MB or body over 4.5 MB (MAX_BODY_BYTES 4,500,000); 429 rate limit (Retry-After); 500 not configured; 502 GitHub failed.relay/README.md
4GET /api/healthAnswers {"ok":true}.relay/api/health.ts
5GET /api/updateQuery target, arch, current_version. Reads the latest release of RELEASES_REPO; 60 s in-memory cache with ETag revalidation; on GitHub 403/429 the last good answer is served; response no-store. 204 when there is no release, no newer one, no bundle and .sig for the platform, or the release is older. Else 200 with the Tauri updater JSON {version, notes, pub_date, url (RELAY_PUBLIC_URL or request origin + /api/download/<id>), signature}. Semver 2.0.0 ordering (a release candidate is older than its release).relay/api/update.ts; relay/lib/semver.ts
6GET /api/download/<asset-id>Asks GitHub with Accept: application/octet-stream and redirect manual, answers 302 with the signed Location. Scoped to RELEASES_REPO. A non-numeric id gives 400.relay/api/download/[id].ts
7POST /api/feedback bodytitle <= 200 (control chars become spaces), description <= 20000, kind bug|idea, appVersion <= 64, os <= 200, logs optional (redacted, then the last 200 KB kept, prefixed "[... N earlier bytes cut]"), screenshot optional base64 (a data: URL prefix is accepted), <= 3 MB decoded, checked by PNG or JPEG magic bytes.relay/api/feedback.ts; relay/lib/feedback.ts
8RedactionPatterns: github_pat_ (50+), sk-ant- (20+), ghp_ (36+), gh[orsu]_ (36+), AKIA (16+), xox[abpr]-, private key blocks (up to 20000 chars), "access_token" and "refresh_token" JSON fields, Bearer tokens.relay/lib/redact.ts
9Flow 1: issueCreate the issue with the CALLER's token. Public body: the description, a table with Kind, App version, OS, and a note about attachments. The relay's own token never creates the issue.relay/api/feedback.ts
10Flow 2: attachmentsWith the relay token commit issues/<n>/{screenshot.png|jpg, logs.txt, report.json} to the private repo FEEDBACK_ATTACHMENTS_REPO as one commit via the Git Data API (3 attempts). report.json: repo, number, url, login, kind, appVersion, os, createdAt.relay/lib/attachments.ts
11Flow 3: labelPATCH the issue with labels ["feedback","type:<kind>"] and the nearest-sprint milestone: the open "Sprint N" with the earliest due date today or later, else the one with the latest due date. If storing failed the body is rewritten with "could not be stored". Answer 201 {number, url}.relay/lib/milestone.ts; relay/api/feedback.ts
12RefusalsGitHub 401: "GitHub no longer accepts your sign-in; sign out and in again". 403: "your account is blocked from the repository, or your sign-in lacks the repo scope". 404: "the repository is not visible to your account". 410: "issues are turned off on the repository". 422: "GitHub rejected the issue". The relay answers 403 (or 422) "GitHub did not let your account open an issue on {repo}: {hint} (GitHub said: {msg <= 200})." A 429, or a 403 with retry-after or x-ratelimit-remaining 0, becomes 429 "GitHub is rate-limiting your account, try again later" with Retry-After (default 60). Any other status becomes 502.relay/lib/feedback.ts; relay/lib/http.ts
13Body errors (400)"{key} is required", "must be a string", "is longer than N characters", "kind must be \"bug\" or \"idea\"", "screenshot must be a PNG or JPEG image", "screenshot is not valid base64", "body must be JSON".relay/lib/feedback.ts
