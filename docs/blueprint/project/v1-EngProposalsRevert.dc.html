1ProposalViewFields: mine, approved_by_me, number, branch, author, title, url, files, approvals, needs_update. 2ApproveNever your own: "you cannot approve your own proposal; another member has to". A member's approval is recorded as a GitHub review. If the proposal is behind the default branch: "proposal #N needs an update before it can be merged".crates/core/src/engine.rs:1243-1250
3Host mergesThe host's sync runs merge_approved when proposalMode is on: a proposal merges only when approved by another current member and not needs_update; otherwise it is forgotten from the cache so it is looked at again next time.crates/core/src/engine.rs
4DeclineCloses the PR with the note "Declined by {login} in claude-sync." An unknown or closed number fails with "proposal #{number} is not open".crates/core/src/engine.rs:1266-1275
5Settingsset_group_auto_accept_claude_md and set_group_proposal_mode are host only. Commit summaries: "auto-accept CLAUDE.md on|off", "proposal mode on|off".crates/core/src/engine.rs:1177,1198
6RevertHost only. Creates a NEW commit putting each allowlisted file back to the target commit's parent content (added files deleted, deleted files restored). Same secret scan and push path with retry as any change; never a force push. If a file changed again after the target commit, the whole revert is refused and names the file, the later commit and its author. A preview writes nothing. After a revert a sync runs.crates/core/src/engine/revert.rs
7History viewAt most MAX_HISTORY_WALK = 20 commits are walked per history request (a longer list is cut).crates/core/src/engine.rs:2189,2210
8Change noteschanges/before-now.json on the default branch (CHANGE_NOTES_PATH), never synced into ~/.claude. change_notes returns an empty list on any problem (missing file, bad JSON, network).crates/core/src/engine.rs:156
9Copy to groupContent of one group the user is in is committed to another (architecture §7b): CLAUDE.md text is redacted and appended under a heading, skills and agents are committed as files, every change secret-scanned first; the target's members get copied CLAUDE.md lines through their review. What is copied is the source group's last synced version, not local edits. The user needs write access to the target; read-only is reported by the preview and the copy. Copy has none of the share-skill checks. The skill or agent must exist in the source and not contain "/"; errors "{from} has no skill named {s}", "{from} has no agent named {a}", "{name} does not sync skills|agents", "{name} already has a different skill|agent named {x}". Commit "copy from {from}: CLAUDE.md, skills/x, agents/y.md, N settings". (The share-skill checks live in engine.rs, see Messages.)crates/core/src/engine/copy.rs:1-10; engine.rs:985-1052
