Engineering rules

Created 2026-11-26. Updated 2026-11-26.

Lint (fails CI)

  • Rust: cargo fmt; clippy -D warnings with unwrap_used, expect_used, panic and todo denied outside tests; cargo-deny for licences and advisories.
  • TypeScript: strict mode, Biome lint and format; no any; the command client is generated from the Rust types (ts-rs) so the two never drift.
  • A mistake made twice becomes a lint rule whose message says how to fix it.

Property tests (proptest)

  • Planner: plan(remote, base, local) applied twice equals once (idempotent); never deletes a file the user changed.
  • MEMORY.md merge: keeps every line either side added; CRLF vs LF alone gives no push.
  • Secret scanner: every pattern in the list is found inside random text; the allow marker passes.
  • Schedule validation: limits of row 73 hold for random input.
  • Path safety: no planned write leaves the managed folders (no .., no absolute, no symlink escape).

Other tests

  • wiremock plays GitHub for every endpoint on the Endpoints frame, including 304, 401, 403 rate limit, 422 and 5xx.
  • Crash test: kill the executor between renames and the base commit; the next tick converges.
  • Playwright plays every scenario on this page against the fake backend, one run per OS webview.

Architecture rules

  • engine has no I/O: it gets traits Remote, Store, Disk and a clock.
  • Only the actor mutates state; the window and tray read snapshots.
  • Every GitHub call goes through one client with the ETag cache and a caller name for the request counts.
