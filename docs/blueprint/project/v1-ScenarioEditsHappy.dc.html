Local edits, conflicts, proposals: happy path

Created 2026-11-26. Updated 2026-11-26.

As a group member, I want to share or propose a change I made locally, so that the group can use it after the host agrees. Click a step to open its screen. See the flow that leads here.

  1. Edit a shared file in an editor
    System: Any change under the managed paths in ~/.claude.
  2. Watcher notices the change
    System: spawn_watcher (crates/core/src/watch.rs:197); local_edits lists them (watch.rs:35).
  3. Group lists "Local changes" with actions
    System: Each edit offers a choice; engine.resolve_edit applies it (engine.rs:971).
  4. Secret scan before any commit
    System: Blocked when a pattern matches (secrets::scan, engine.rs:410), unless the line has claude-sync: allow-secret.
  5. Host: commit; member: open proposal PR
    System: Proposal branch name is proposal/<login>-<UTC> (remote.rs:90, 106).
  6. Host clicks Approve or Decline
    System: Open proposals are re-read only when a PR head sha or updated_at changed (proposals_changed).
  7. Approved change reaches every member
    System: The next sync tick of each member applies it (SyncTick flow).
  8. State: Open (PR from proposal/ branch)
    System: state open in Proposal states (crates/core/src/remote.rs:90-106; docs/architecture.md section 5c).
  9. State: Approved: merged
    System: state approved in Proposal states (crates/core/src/remote.rs:90-106; docs/architecture.md section 5c).
  10. State: Declined: closed
    System: state declined in Proposal states (crates/core/src/remote.rs:90-106; docs/architecture.md section 5c).
