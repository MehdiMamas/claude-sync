Send feedback: edge cases

Created 2026-11-26. Updated 2026-11-26.

As a user, I want to see what happens when it goes wrong while I send a problem report from the app, so that the maintainer sees it with logs even then. Click a step to open its screen. The flow behind it.

Acceptance criteria: The user sees what went wrong in words, and what to do next. Nothing is lost or half-written.
  1. Write what happened
    System: Logs and screenshot are optional.
  2. Empty: write a few words first
    System: Checked in the window; nothing is sent.
  3. POST to the relay with the user token
    System: The relay checks the token with GitHub, files the issue as the user, stores attachments privately. Calls POST /api/feedback.
  4. GitHub refused: not sent, text kept
    System: The relay passes the reason through.
  5. Too large: edit and send again
    System: The relay caps the request body.
  6. Rate limited: saved, sent later
    System: GitHub 429 or the relay limit per user.
  7. Offline: saved, sent when back
    System: The engine retries after GET /api/health answers ok. Calls GET /api/health.
  8. Also: Settings: notifications blocked
    System: state "error: system blocks notifications".
