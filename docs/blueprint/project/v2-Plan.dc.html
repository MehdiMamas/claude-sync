Steps, each with its check

  1. repo formats. Check: fixtures copied from real v1 group and personal repos (sample data only) read and written back byte for byte, unknown keys kept.
  2. engine planner and merges. Check: proptest suite green.
  3. github client against wiremock. Check: every Endpoints row has a test.
  4. store and import_v1. Check: imports a fixture v1 state folder holding every v1 file; a test fails on any file the importer does not know.
  5. fs executor and crash test. Check: kill test converges.
  6. CLI parity. Check: every AGENTS.md command answers with the same exit codes.
  7. shell and tray. Check: tray menu items of Parity row 56.
  8. UI screens. Check: Playwright plays every scenario frame.
  9. updater and release.yml. Check: a test release updates a v2 install; a real v1 install on each OS updates through the relay to v2, then sign-in, groups, the CLAUDE.md import, jobs, autostart, queued feedback and the CLI service all still work; on Windows, uninstalling v2 leaves no task under \claude-sync\ and an update keeps them.
  10. v1 daemon hand-over. Check: on Ubuntu 24.04 with a systemd user unit and on a cron-only host: a running v1 0.1.27 daemon, then claude-sync-cli update to 2.0.0 and claude-sync-cli status: the v1 process is gone within 30 s, a v2 daemon runs, store.db is imported once; a v1 daemon held with SIGSTOP gives the waiting state, exit 1 and no file written.
  11. relay. Check: pnpm -C relay test: a v1 check increments the day counter and a 2.0.0 check does not; Redis down still answers; /api/v1-checks refuses a non-owner; linux/aarch64 answers with the CLI archive only when its .sha256 exists; a v1 0.1.27 CLI on the arm64 runner updates to the test release.
  12. bench job. Check: all budgets green on three OSes.
  13. parity walk. Check: tester does the v1 daily tasks on v2; Parity table checked row by row.
