Local edits, share, propose, revert: edge cases

Created 2026-11-26. Updated 2026-11-26.

As a host or member, I want to see what happens when it goes wrong while I share (host) or propose (member) a change I made locally, so that the group can use it after another member approves and the host merges even then. Click a step to open its screen. The flow behind it.

Acceptance criteria: The user sees what went wrong in words, and what to do next. Nothing is lost or half-written.
  1. Share: preview the diff
    System: engine::secrets::scan runs on every line before the preview shows.
  2. Secret found: share refused
    System: The scan names the file and line; a line with claude-sync: allow-secret passes.
  3. Fast-forward main
    System: force is never used; 422 means someone pushed first. Calls PATCH /repos/{owner}/{repo}/git/refs/heads/main.
  4. 422: someone pushed first, re-plan and retry once
    System: Re-read the head, re-plan on it, one more try.
  5. 422 again: remote wins, copy saved
    System: The local copy goes to Conflicts; the user can share it again.
  6. Open the proposal pull request
    System: Base main; shows on every member's Proposals card on their next tick. Calls POST /repos/{owner}/{repo}/pulls.
  7. Host declines (or Decline all)
    System: The pull request is closed; the author keeps the change locally. Calls PATCH /repos/{owner}/{repo}/pulls/{n}.
  8. Main moved: tagged "needs an update"
    System: The author updates it from the app; approvals are read again.
