Send feedback: happy path

Created 2026-11-26. Updated 2026-11-26.

As a user, I want to send a problem report from the app, so that the maintainer sees it with logs. Click a step to open its screen. The flow behind it.

Acceptance criteria: Logs are redacted on the machine. Offline reports are sent later.
  1. Write what happened
    System: Logs and screenshot are optional.
  2. Redact logs on the machine
    System: Tokens are removed; paths and repo names can show (as v1).
  3. POST to the relay with the user token
    System: The relay checks the token with GitHub, files the issue as the user, stores attachments privately. Calls POST /api/feedback.
  4. Issue created
    System: The issue number shows; the triage reply comes on the issue.
  5. Notification: reply on the issue
    System: The in-app list and a desktop notification.
  6. Also: Settings: notifications
    System: state "default".
  7. Also: Notifications: empty
    System: state "empty: none".
